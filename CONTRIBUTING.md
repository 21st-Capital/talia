# Contributing to Talia

Thank you for your interest in Talia.

## Issues are welcome

Open an issue for a bug, a question about the code, or an idea. A good report
says which build you ran (the App Store app, TestFlight, or your own build and
its flags), the iPhone and iOS version, what you did, what you expected and what
happened. Never post a seed phrase, a private key, an xpub of a wallet that holds
real coins, or a screenshot that shows one. Use test vaults on Testnet4.

Security problems do not go into issues: see [SECURITY.md](SECURITY.md).

## Pull requests are not accepted for now

This repository is a copy of the private development repository, refreshed at
every App Store release, so a pull request here cannot be merged as it is. For
now we do not accept outside pull requests. If you have a change in mind, open
an issue and describe it; a change we take on is made in the private repository
and reaches this copy with the next release.

## How the code is written

These are the rules the project follows. They matter if you read the code, open
an issue about it, or keep a fork of your own.

### Neutral style

Everything that may be published (comments, tests, docs and commit messages) is
written so that it holds without the people behind it:

- A decision says "decided <date>" or "after a phone test on <date>", or states
  the rule itself. It never names a person or quotes one by name.
- No email address other than ones at the example domains (`example.com`,
  `example.org`, `example.net`), apart from the company addresses the app itself
  shows a client (listed in `scripts/public-export-scan.js`); no names of
  customers or testers, no account numbers, no internal machine names, and no IP
  addresses outside the documentation and private ranges tests use.
- No review or audit finding numbers, ticket numbers or references to private
  documents: describe the rule.
- Test keys come from published test vectors (BIP-32's test vectors, the
  "abandon ... about" mnemonic, the BIPs' own examples) or are plainly made up.
  The exceptions are known and kept on purpose: the testnet keys of the two test
  devices the hardware fixtures were recorded on, and 21st Capital's own public
  keys and fingerprints: those the app pins to check what the backend sends, and
  the fingerprints of its testnet key pools, which tests use. No other key,
  fingerprint or address of a real device or wallet.

### Words a client reads

- Plain words: say coins, never inputs or outputs, and never outpoint.
- No em dashes in a string a client can see (`importProviders.test.ts` and other
  tests check the screens' words).
- A dialog is a title and its buttons; a reason goes behind an info dot.
- A sentence about a vault must be true for every vault it can appear on: it
  never guesses whose key a path holds.

### Design and hardware

The screens follow [docs/design-rules.md](docs/design-rules.md) and the signing
flows [docs/hardware-signing.md](docs/hardware-signing.md). Structural tests in
`src/ui/__tests__/` hold the code to both notes, so a change to a rule goes into
the note and its test in the same commit.

### Tests

- Logic lives in pure modules (no native import), so it is tested in Node with
  jest; a new rule comes with its test.
- All Bitcoin logic goes through BDK or the audited `@scure` and `@noble`
  libraries; nothing hand-rolls derivation, coin selection or signing. The phone
  never holds a private key, and a descriptor carrying one is refused.
- Before a change is committed, `npx tsc --noEmit` and the whole of `npx jest`
  pass. Run them from a git clone: several tests read git.
- A fixture made by a program has its generator committed beside it where the
  generator can be published (`scripts/liana-*-fixture/`,
  `scripts/cosign-request-fixture.mjs`), so anyone can make it again. The others
  are frozen recordings and say where they came from: the engine fixtures written
  by the library fork's equivalence harness, the key-proof vectors made once with
  21st Capital's key tooling, and the bridge calls recorded from the simulator
  harness. They are never regenerated by hand.
